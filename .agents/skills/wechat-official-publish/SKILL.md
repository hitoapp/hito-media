# 微信公众号推文生成器

将产品功能转化为用户可感知的价值,生成适合微信公众号发布的HTML推文。

## 核心理念

好的推文不是功能说明书，而是用户故事。要让读者看完后觉得“这正是我需要的”，而不是“这个功能很厉害”。

推文内容不宜过长，控制在 **800-1200字** 为宜。过长的文章容易让读者失去耐心。

## 工作流程

### 第一步：理解功能

在动笔之前，先在代码库中找到相关页面和代码，真正理解这个功能：

1. **定位页面**：根据用户提到的功能名称，在 `src/pages/` 或分包目录中搜索对应的 `.mpx` 文件
2. **阅读代码**：查看页面的 template（理解UI结构）、script（理解业务逻辑）、style（理解视觉呈现）
3. **追踪类型**：在 `src/api/hitoapi/types.ts` 中找到相关的接口类型定义，理解数据模型
4. **查看组件**：阅读页面引用的子组件，理解功能的完整交互流程

只有真正理解了功能，才能写出准确、有说服力的推文。不要凭想象写，要基于代码实现来写。

### 第二步：撰写推文

理解功能后，按照以下结构撰写推文。

## 推文结构

采用 **痛点 → 方案 → 价值** 的三段式叙事:

### 1. 痛点引入

用场景化的问题引起共鸣,让读者点头说"对对对,我就是这样"。

写法要点:
- 描述具体场景,不要抽象概念
- 每个痛点控制在2-3句话
- 痛点数量2-3个为宜,不要超过4个

### 2. 方案呈现

介绍产品如何解决这些痛点,重点是"能做什么"而不是"怎么实现的"。

写法要点:
- 每个能力用一句话概括价值,再用2-3句话展开说明
- 避免技术术语,用用户语言

### 3. 价值升华

展示使用前后的对比,让读者直观感受到价值。

- 给出具体数字或案例(即使是示例数据)
- 总结为可记忆的一句话
- 结尾用品牌slogan收束:"喜多 -- 私域活动运营专家"

## HTML排版规范

### 基础结构

```html
<div style="max-width: 600px; margin: 0 auto; background-color: #fff; padding: 20px; font-family: -apple-system, BlinkMacSystemFont, 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', sans-serif; color: #333; line-height: 1.8; font-size: 16px;">
  <!-- 内容区 -->
</div>
```

### 样式要点

**必须使用内联样式**,公众号编辑器不支持外部CSS。

**主题色**:默认 #ff5271(喜多品牌色)。

**字号层级**:
- 大标题:22px,居中,加粗
- 小标题:18px,主题色,左侧3px边框
- 正文:16px,#333或#555
- 辅助文字:14px,#888

**间距**:
- 段落间距:15px
- 卡片内边距:20px
- 卡片外边距:20px 0

**卡片样式**:
```html
<div style="background-color: #fafafa; border-radius: 8px; padding: 20px; margin: 20px 0;">
  <!-- 卡片内容 -->
</div>
```

**分割线**:
```html
<div style="border-top: 1px dashed #ddd; margin: 25px 0;"></div>
```

**引用块**:
```html
<blockquote style="border-left: 3px solid #ff5271; padding-left: 15px; color: #666; font-style: italic; margin: 20px 0;">
  引用内容
</blockquote>
```

## 输出要求

1. 输出完整的HTML文件,包含DOCTYPE、head、body
2. 内容区使用单层div包裹,方便复制
3. 所有样式必须内联,确保可直接复制到公众号编辑器
4. 需要配图的位置用占位符标注,格式为:

```html
<!-- 图片占位: [图片描述] -->
<div style="background-color: #f0f0f0; border-radius: 8px; padding: 40px; text-align: center; color: #999; font-size: 14px; margin: 20px 0;">
  [图片描述]
</div>
```

图片描述应具体说明此处需要什么图,例如"活动数据看板截图"、"渠道码列表页面"、"用户状态分析图表"等,方便后续替换为真实图片。

## 保存要求

生成的公众号HTML文件必须保存到当前媒体仓库的发布目录：

```text
publish/official-account/YYYY-MM-DD-主题/
```

日期使用当前日期，主题使用简短中文短语。HTML文件建议命名为 `文案.html`；如同时整理标题、摘要、配图说明等辅助内容，可在同一目录下保存 `素材说明.md` 或 `发布记录.md`。

## 使用示例

用户输入:
> 帮我写一篇介绍渠道码功能的公众号推文

输出:
生成完整的HTML文件,包含:
- 引言:用问题引起共鸣
- 痛点场景:描述多渠道推广效果无法追踪的困扰
- 功能介绍:渠道管理、独立二维码、数据看板
- 价值对比:以前凭感觉 vs 现在看数据
- 结尾:品牌slogan

## 进阶用法

### 调整叙事结构

某些场景可能需要调整结构:
- 产品发布公告:方案 → 新特性 → 升级指引
- 教程类文章:场景 → 步骤 → 效果
- 案例分享:背景 → 挑战 → 解决方案 → 成果

根据用户需求灵活调整,但保持"以用户价值为中心"的核心原则。
