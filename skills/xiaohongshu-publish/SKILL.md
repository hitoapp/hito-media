# xiaohongshu-publish

## 目标

围绕喜多（HITO）产品宣传完成两类工作：

1. 基于产品主题、用户截图、功能说明或项目级产品改动摘要，总结产品特性、运营价值和用户场景，生成小红书内容。
2. 生成可供用户手动发布的小红书素材包，包括标题、正文、配图、话题建议、发布说明和记录模板。

默认内容目标是展示喜多产品专业度、解释新功能，并向现有客户说明产品解决了哪些具体问题。优先把技术改动转译成用户能理解的产品价值，不直接堆技术细节。

## 强制约束

- 不要自动操作小红书创作服务平台，不要接管 Chrome 发布，不要点击上传、预览或发布按钮。
- 即使用户说“帮我发布”“发出去”，也只生成或整理手动发布所需素材，并提醒用户自行发布。
- 不要使用 DOM 脚本注入、Chrome 扩展、Playwright、Computer Use 或系统级鼠标键盘来完成小红书后台发布。
- 可以给出手动发布步骤、话题模板提示、复制用正文和素材路径，但实际发布动作由用户完成。
- 如果用户发布后提供链接、截图或数据，再协助更新 `发布记录.md` 和做复盘。

## 产品素材输入

本 skill 不维护项目级素材整理流程或发布归档流程。这些工作放在项目级文档中。

生成小红书内容前，优先使用以下输入：

- 用户明确提供的产品主题、截图、功能说明或操作流程。
- 已经按项目级流程整理好的产品改动摘要或可宣传改动候选清单。
- 当前项目目录中已有的发布素材、复盘记录或同主题公众号/小红书稿件。

如果用户只说“基于最近改动写小红书”，先按项目级文档取得产品改动摘要，再回到本 skill 做小红书表达。不要在本 skill 中维护或复述项目级流程。

## 内容生成要求

生成正式内容前，不要直接给最终稿。先输出“内容策略确认卡”，让用户逐步确认方向。

### 内容策略确认卡

默认先给用户以下选项和建议：

- 发布目标：默认“展示产品专业度 + 解释新功能 + 服务现有客户”。
- 目标读者：结合改动判断，常见读者包括社团负责人、活动运营者、组织管理者、合作方或已有客户。
- 小红书默认风格：产品更新日志。
- 小红书可切换风格：创业者分享、客户案例、活动运营干货、轻量种草。
- 内容类型建议：结合产品素材或项目级产品改动摘要，从产品更新、功能教程、场景问题、客户案例、避坑提醒、运营方法中选择。

策略确认卡之后，先列“候选主题”，不要直接写最终文案。每个候选主题包含：

- 主题名称
- 核心卖点
- 适合风格
- 建议配图方向
- 需要用户确认的问题

用户选择主题后，再给 2-3 种文风样稿。样稿只需要短，不要一次写成长文。用户确认标题、正文方向和配图方向后，才进入正式内容生成或图片生成流程。

正式稿确认前，不要写入 `publish/` 文件夹。只有用户确认标题、正文、配图方向和平台后，才创建发布目录并保存文件。

### 小红书

小红书内容应更口语、更场景化，突出一个清晰卖点，适合配图传播。默认使用“产品更新日志”风格，写作时像是在认真说明一次产品能力升级，而不是写内部版本说明。

生成小红书内容时，借鉴小红书运营方法，但要适配喜多的产品属性：

- 真实有用优先：不要写成硬广，不夸大功能效果，不虚构客户数据或使用结果。
- 场景先行：先讲活动组织、社团管理、报名签到、分享传播、接入方管理等真实问题，再引出喜多功能。
- 细节可信：如果有产品截图、项目级产品改动摘要、真实功能入口、操作路径或后台字段，优先用这些细节增强可信度。
- 适度克制：可以表达推荐和价值判断，但避免“神器”“吊打”“必备”等过度营销词。
- 合规安全：不刷量、不诱导违规互动，不使用容易引发平台限流或误解的敏感表达。
- 避免消费品模板：不要套用“后悔没早买”“平替”“智商税”等与喜多产品气质不符的爆款话术，除非用户明确要求强种草风格。

默认输出：

- 标题候选 3-5 个
- 正文 1-2 版，或在用户尚未确认风格时先输出 2-3 种短样稿
- 小红书话题建议（默认不直接写入正文；用于用户手动发布时选择话题模板或话题组件）
- 配图建议
- 手动发布前需要用户确认的问题

### 小红书手机端可读性

小红书正文必须优先按手机端阅读体验生成，不要写成长段落文章。

硬性要求：

- 正文默认控制在 300-450 个中文字符左右；如果功能复杂，最多不超过 550 个中文字符。
- 相比公众号或内部说明，主动压缩约 1/3 内容，只保留一个核心卖点、一个典型场景和一个产品价值结论。
- 每段 1-2 句，单段尽量不超过 45 个中文字符。
- 段落之间必须保留空行，不允许整段文字粘在一起。
- 第一屏正文应在 3-5 行内说清“这篇在讲什么”，不要用长铺垫。
- 表情可以少量使用，用来分隔节奏或强化语气；不要让表情代替产品说明。
- 默认不要在正文末尾追加 `#xxx` hashtag。实测普通输入的 hashtag 不一定成为有效小红书话题，反而影响阅读。
- 如果用户明确需要话题，正文里仍优先保留自然表达；提醒用户手动发布时使用小红书页面的“话题模板”或话题组件。

推荐正文结构：

1. 标题式开场：一句话点出问题或更新。
2. 场景说明：说明谁会遇到这个问题。
3. 功能更新：说明喜多这次做了什么。
4. 用户价值：说明参与者、组织者或客户得到什么。
5. 收束：一句克制总结。

生成发布素材前必须检查正文的手机端可读性：

- 如果用户提供手机截图中出现大段文字粘连，必须重新分段并压缩正文。
- 如果正文超过手机一屏仍没有明显停顿，优先删减解释性句子，不要继续补充背景。
- 如果用户提供发布后的手机截图指出可读性问题，要把该问题总结进 skill，并在后续发布前优先规避。

建议笔记结构：

1. 痛点共鸣：用 1-2 句话说清楚活动运营者或组织管理者遇到的问题。
2. 更新引入：自然说明“这次喜多更新解决了什么”。
3. 功能说明：用具体功能点、页面变化或流程变化解释怎么解决。
4. 使用场景：说明适合哪些客户、活动或组织场景。
5. 克制总结：说明改动带来的效率、管理清晰度或体验提升，不要夸大。

可选内容矩阵：

- 产品更新：适合发布版本新能力，结构是“问题 -> 更新 -> 适用场景 -> 使用价值”。
- 功能教程：适合已有客户，结构是“入口在哪里 -> 怎么操作 -> 能解决什么”。
- 创业者分享：适合解释产品判断，结构是“观察到的问题 -> 为什么要做 -> 做成什么样 -> 后续计划”。
- 客户案例：适合有真实案例时使用，结构是“客户场景 -> 遇到的问题 -> 使用喜多后的变化”，不要虚构结果。
- 避坑提醒：适合活动运营方法论，结构是“常见误区 -> 风险 -> 喜多如何帮助管理”。

标题策略：

- 标题尽量控制在一眼能读完的长度，包含核心关键词，例如“活动运营”“社团管理”“报名签到”“分享统计”“接入方管理”。
- 默认不要使用强标题党。可以用“终于把这个问题理顺了”“这次更新主要解决一个管理细节”“活动运营后台又补了一块能力”这类真实口吻。
- 如果用户选择“客户案例”或“活动运营干货”风格，可以把标题写得更问题导向，例如“活动分享出去后，怎么知道谁真的被带来了？”

封面和配图策略：

- 优先使用产品截图、前后对比图、流程图或后台能力示意图。
- 小红书配图建议使用竖版 3:4；如果是截图拼图，要保证文字清晰，不要过度装饰。
- 封面要突出一个关键词或一句短问题，不要塞满功能点。
- 图片保持真实、清楚、可检查，不要做成过度广告海报。

话题策略：

- 默认不在正文中写入原始 hashtag。
- 可以给出 3-5 个“小红书话题建议”，例如“活动运营”“社团管理”“小程序工具”“活动报名”“产品更新”，但只作为用户手动发布时使用平台话题组件的参考。
- 如果用户已配置小红书话题模板，优先提醒用户在发布页正文输入框下方点击“话题”按钮右侧向下箭头，进入“管理/使用模板”，选择“喜多产品”模板应用；正文文件中不要手写这些 hashtag。
- 如果用户明确要求手写 hashtag，可单独提供一个“备选 hashtag”区块，不默认混入正文。
- 不要使用与内容无关的热门话题。

发布后复盘建议：

- 如果用户要求持续运营，记录每篇笔记的发布时间、主题、标题、封面方向和数据表现。
- 复盘指标优先看阅读/曝光、点赞、收藏、评论、主页访问、私信咨询和关键词搜索反馈。
- 不要只追求单篇爆款；喜多这类产品更需要长期沉淀“活动运营”“社团管理”“小程序工具”等搜索资产。

可选风格参考：

- 产品更新日志：清楚说明这次更新解决了什么问题、适合谁、怎么用。
- 创业者分享：从“我们为什么做这个功能”切入，解释产品判断和场景观察。
- 客户案例：用一个具体运营场景讲问题、使用方式和结果。
- 活动运营干货：先讲运营痛点，再带出喜多功能作为解决方案。

所有内容都要围绕“宣传喜多产品特性或改动”，避免写成内部开发日志。

## 发布文件存放

生成内容时，按平台保存到当前项目目录：

```text
publish/xiaohongshu/YYYY-MM-DD-主题/
```

日期使用当前日期。主题使用简短中文短语，例如：

```text
publish/xiaohongshu/2026-06-11-接入方管理升级/
```

平台目录固定使用英文 `publish/xiaohongshu/`，便于在不同工具和平台之间查找、复制和归档素材。

建议保存：

- `文案.md`
- `素材说明.md`
- `生成配图/`：封面图、正文图、产品截图、拼图或生成图片
- `发布记录.md`：发布状态、发布时间、平台链接、后续数据记录
- 如有发布后手机端截图或复盘意见，可追加到 `发布记录.md` 的“发布后复盘”部分。
- `手动发布说明.md`：给用户复制标题、正文、图片路径、话题模板和检查清单。

写入与归档规则：

1. 先在对话中确认标题、正文、配图方向和发布平台。
2. 用户确认前，不要写入正式发布文件。
3. 用户确认后，创建对应主题目录并保存确认稿和生成配图。
4. 生成 `手动发布说明.md`，至少包含：
   - 标题
   - 正文
   - 配图绝对路径
   - 话题模板提示：在小红书发布页正文输入框下方，点击“话题”按钮右侧向下箭头，进入“管理/使用模板”，选择“喜多产品”模板应用
   - 手动发布检查清单：图片、标题、正文分段、话题模板、发布前预览
5. 用户手动发布成功后，如果提供链接、截图或发布时间，再更新 `发布记录.md` 供后续复盘。

## 手动发布素材检查

生成交付前确认：

1. 图片文件存在，并提供绝对路径。
2. 标题是最终确认版本。
3. 正文是最终确认版本，且没有把话题模板里的 hashtag 手写进正文。
4. 正文在手机端可读：短段落、少长句、有自然停顿。
5. `手动发布说明.md` 能让用户直接复制标题和正文。

## 实操经验

- 小红书创作服务平台对自动化操作不稳定，Chrome 扩展、DOM 读取、截图、上传和点击发布都可能卡住或失败；不要再把自动发布作为 skill 目标。
- 后续小红书发布由用户手动完成，Codex 只负责准备内容、图片、话题建议、发布说明和记录文件。
- 正文末尾不要默认追加原始 `#xxx` hashtag；需要话题时优先使用小红书“话题模板”，当前常用模板为“喜多产品”。
- 桌面端预览不能完全替代手机端阅读效果；生成时要优先按手机端短段落和低信息密度处理。
